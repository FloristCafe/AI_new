# MovieLens 1M SASRec Baseline 下一步推进笔记

## 1. 这份笔记要解决什么

当前 `movielens_1m_sasrec_baseline` 已经完成了：

- 数据清洗与序列化
- SASRec baseline 跑通
- `valid` 集评估
- `best checkpoint` 选择
- `early stopping`
- 第一版 test 指标产出

所以接下来的问题已经不是“这个项目能不能跑”，而是：

- 下一步到底优先优化什么
- 是继续调超参数，还是改数据处理
- 什么算正常项目推进，什么算过早复杂化

这份笔记的目的，就是把这个阶段之后的推进顺序固定下来。

## 2. 当前阶段的判断

当前项目已经从“单次 baseline 训练”进入“实验化阶段”。

这意味着后续工作不应该再以“想到一个点就手动跑一个命令”的方式推进，而应该切换到更稳定的实验节奏：

1. 明确当前要验证的假设
2. 用小批量消融实验回答问题
3. 把结果沉淀成可比较的 summary
4. 再决定下一层升级方向

也就是说，当前阶段最重要的不是“马上换更复杂模型”，而是先把“哪条优化主线最值得继续走”判断清楚。

## 3. 下一步最应该做的事情

下一步最合理的工作，不是再去大改模型结构，而是：

**完成第一轮系统化消融实验。**

这一轮实验的作用，不是为了把分数一口气冲高，而是回答两个最关键的问题：

1. 当前瓶颈更像是历史窗口太短，还是模型容量不够。
2. 当前 baseline 的提升，更适合从数据视角推进，还是从结构视角推进。

### 3.1 第一轮实验主题

建议先跑一组最小、最关键、最容易解释的三组实验：

- baseline：`max_seq_len = 50`, `embedding_dim = 64`, `dropout = 0.2`
- 长序列：`max_seq_len = 100`, `embedding_dim = 64`, `dropout = 0.2`
- 大容量：`max_seq_len = 50`, `embedding_dim = 128`, `dropout = 0.2`

这三组实验对应三个问题：

- baseline：当前正式基线到底是什么
- `seq_len 100`：更长历史是否明显有帮助
- `dim 128`：更大表示容量是否明显有帮助

这比直接同时乱改多个超参数更有价值，因为每一条实验都有明确问题指向。

### 3.2 第一轮实验之后怎么判断

这一轮实验跑完后，不是看单个 test 数字就结束，而是要做结构化判断。

重点看：

- `best_valid_ndcg_at_10`
- `best_valid_hr_at_10`
- `test_ndcg_at_10`
- `test_hr_at_10`
- `best_epoch`
- 是否 early stopping

判断逻辑如下：

#### 情况 A：`seq_len = 100` 明显优于 baseline

这说明：

- 当前模型更缺历史上下文，而不是缺容量
- 下一阶段应优先沿数据与序列建模方向推进

后续更自然的动作是：

- 继续探索 `max_seq_len`
- 研究时间信息
- 研究 session 化或 recency 特征

#### 情况 B：`embedding_dim = 128` 明显优于 baseline

这说明：

- 当前模型表达容量不够
- 下一阶段更适合先沿模型容量与正则化方向推进

后续更自然的动作是：

- 继续试 `embedding_dim`
- 试 `num_blocks`
- 试 `dropout`

#### 情况 C：两者都没有明显提升

这说明：

- 当前第一版 SASRec 已经接近这套训练目标和数据构造下的平台
- 下一阶段单纯调容量与历史长度的边际收益有限

这时更该推进的就不是超参数，而是：

- 数据处理策略升级
- 训练目标升级
- 采样策略升级

## 4. 之后的大方向优化主线

如果把项目后续真正的大方向分层，建议按下面顺序推进。

### 第一层：实验协议稳定化

这一层现在已经基本打通，但后续还要保持一致：

- `leave-one-out`
- `valid/test` 指标固定
- `best checkpoint` 选择规则固定
- `early stopping` 规则固定
- summary 汇总格式固定

这一层解决的是：

**后面的所有比较是否可信。**

### 第二层：数据处理策略升级

这是最容易带来“不是单纯调参”的真正变化的一层。

可以考虑的方向包括：

- `min_user_interactions`
- `min_item_interactions`
- `max_seq_len`
- 是否保留重复交互
- 是否引入时间间隔特征
- 是否引入 session 划分
- 是否做 item 过滤策略调整

这一层解决的是：

**模型到底看到了什么问题定义。**

### 第三层：训练目标与采样策略升级

当前版本使用的是：

- full ranking softmax
- next-item cross-entropy

后续更值得探索的升级包括：

- sampled negatives
- ranking loss
- negative sampling loss
- in-batch negatives

这一层解决的是：

**模型在用什么目标学习排序。**

### 第四层：模型结构升级

只有在前三层都比较稳后，才值得认真推进大结构升级。

可以考虑的路线包括：

- 更原味的 SASRec block 对齐
- 更深的 Transformer
- user embedding
- 时间编码
- BERT4Rec
- TiSASRec

这一层解决的是：

**模型表达能力的上限够不够。**

## 5. 当前阶段不要急着做什么

当前不建议立刻做下面这些事：

- 直接切换到更复杂的 Transformer 变种
- 过早引入 RL agent
- 直接搞大规模 AutoML
- 一上来就做大量无控制变量的混合实验

原因不是这些方向没价值，而是：

- 当前还处在“先确认主瓶颈在哪”的阶段
- 如果太早上复杂方法，后续很难讲清楚提升来源

换句话说，现在最重要的是：

**先知道该往哪里优化，再决定用多复杂的方法。**

## 6. 项目下一步的推荐顺序

基于当前阶段，推荐按这个顺序推进：

1. 先完成第一轮三组最小消融实验
2. 用 summary 判断当前主瓶颈是历史长度还是模型容量
3. 再决定第二轮是走：
   - `capacity_and_regularization`
   - 还是进一步扩展序列长度与数据策略
4. 跑完第二轮后，再写阶段性项目笔记

这样推进的好处是：

- 每一步都能回答一个明确问题
- 不会过早陷入盲目调参
- 后续写项目总结、做复盘、准备更大改动时，证据链会很清楚

## 7. 当前最简结论

对这个项目来说，眼下最合理的“下一步”不是：

- 再去散着试很多参数
- 或直接大改模型

而是：

**先用一轮最小系统化消融，判断后续主线到底应该优先走“历史窗口与数据策略”，还是“模型容量与正则化”。**

一句话概括：

**当前阶段最重要的不是继续把项目当成单次训练脚本，而是把它真正推进成一个可比较、可判断、可决策的序列推荐实验项目。**
