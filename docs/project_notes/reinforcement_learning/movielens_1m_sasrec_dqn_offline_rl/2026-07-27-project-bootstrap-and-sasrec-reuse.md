## 当前项目会直接复用的内容

### 1. 数据源本身

直接复用：

- `MovieLens-1M`

不需要下载新数据。

核心原因是：

- 这个数据集已经在前序项目里被清洗为交互序列
- 用户历史长度足够支持序列建模
- 时间戳顺序已经可用
- item ID 映射已经稳定

本项目的离线 RL 视角只是改变了“如何解释同一份序列”，不是更换数据集。

### 2. 用户序列的时间有序性

前序项目里已经完成了：

- 按 `timestamp` 对每个用户的历史交互排序
- 把行为序列转成固定窗口输入

这对当前项目是关键前提。

因为在当前离线 RL 项目中：

- `state S_t` 本质上仍然是用户截至时间步 `t` 的有序前缀历史
- `next_state S_{t+1}` 是窗口右移后的后继状态

如果没有上游项目已经建立好的时间有序序列，本项目就无法可靠地构建马尔可夫轨迹。

### 3. 固定长度状态表示约定

前序项目已经把状态表示规范化为：

- 最近 `50` 个 item ID
- 不足长度时左侧零填充

这个表示法会被当前项目直接继承。

原因是：

- 它已经能稳定喂给 `SASRec`
- 它天然适合作为 RL 状态张量
- 它能让离线经验池中的 `(S_t, S_{t+1})` 保持统一形状

因此，本项目里的状态不需要重新发明，而是直接复用前序项目的序列张量约定。

### 4. item ID 映射体系

前序项目已经完成了：

- 原始 `movie_id -> 连续映射 item_id`
- `item_id_mapping.csv`
- `metadata.json` 中的 item 规模记录

这一部分对当前项目非常重要，因为：

- `DQN` 的动作空间必须是固定、连续的索引空间
- `Q-head` 需要输出与候选 item 数量严格对齐的 Q-value 向量

也就是说，前序项目中的 item 重映射并不是“预处理细节”，而是当前离线 RL 项目动作空间定义的基础。

### 5. `SASRec` 编码器实现

前序项目已经有：

- item embedding
- positional embedding
- causal self-attention 编码器
- 取最后一个有效隐藏状态的接口
- 全量 item 打分接口

当前项目不会重写“用户序列感知模块”的核心思路，而是复用这套 `SASRec` 编码器作为状态编码器。

在当前项目里，它的职责会从：

- “给下一个 item 做监督学习打分”

变成：

- “把用户最近 50 步行为编码成一个稠密状态表示”

也就是：

- 前序项目里的 `sequence encoder`
- 在当前项目中升级为 `state encoder`

### 6. 最后一个隐藏状态作为用户当下意图

前序项目已经明确采用了：

- 从最后一个有效位置抽取隐藏状态

这件事在监督学习版本里用于 next-item 预测，在当前项目里会被直接升级为：

- 当前 RL 状态的稠密意图向量

也就是说，本项目中 `Q-head` 的输入，并不是整条序列平均池化结果，而是：

- `SASRec` 编码后的最后一个隐藏状态

这是一个非常直接的工程复用点。

### 7. Leave-one-out 的验证/测试协议

前序项目已经建立了：

- 倒数第二次交互作为验证目标
- 最后一次交互作为测试目标

这一协议仍然对当前项目有价值。

虽然当前项目会增加“轨迹累计奖励”这种 RL 风格指标，但在 next-item 推荐质量层面，仍然可以继续保留：

- `HR@10`
- `NDCG@10`

这意味着：

- 新项目并不需要推翻原有测试切分方式
- 可以在原有离线序列测试协议上，追加 RL 风格评估

### 8. 已有推荐评估函数与结果解释框架

前序项目已经写好了：

- 测试集排序评估脚本
- `HR@10`
- `NDCG@10`
- 历史 item 屏蔽逻辑

这些内容不会原封不动照搬，但会成为当前项目评估模块的重要底层参考。

因为即使换成 `DQN`：

- 模型最终仍然要在候选电影集合中做动作排序
- top-k 是否命中真实下一项，仍然是最重要的业务指标之一

因此，当前项目的离线回测，不会脱离前序项目已经建立起来的评估语言体系。

### 9. 训练产物与 checkpoint 资产

前序项目里已经有：

- `sasrec_best.pt`
- `sasrec_final.pt`

这些 checkpoint 的价值不在于“最终 CE 指标最好”，而在于：

在当前项目中，这些权重可以被当作：

从工程角度看，这意味着新项目不必先从随机初始化开始学习用户序列表示，而是可以站在一个已经具备序列模式感知能力的表示层上，继续学 Q-value 决策。

## 当前项目不会直接照搬的部分

为了避免概念混淆，也要明确哪些内容不会被直接沿用。

### 1. 监督学习目标函数

前序项目里的：

- `CrossEntropy`
- `BCE + negative sampling`

都不是当前项目的最终训练目标。

当前项目要学习的是：

- `Q(s, a)` 价值函数

因此训练逻辑会切换到：

- 离线经验采样
- Bellman target
- Double DQN 更新

### 2. 单步分类式训练样本

前序项目中的很多训练样本是围绕：

- `history -> next_item`

构造的。

当前项目则需要明确构造成：

- `(S_t, A_t, R_t, S_{t+1}, Done)`

也就是说，当前项目不会继续把数据仅仅看作监督学习的 `X, Y` 样本对，而是要改造成可回放的离线轨迹。

### 3. 只看排序指标的训练过程

前序项目里训练阶段的核心是：

- 每个 epoch 跑验证集
- 看 `valid NDCG@10`

当前项目后续除了排序指标，还会新增：

- TD loss
- 平均 Q 值
- 目标 Q 值稳定性
- 轨迹累计奖励

也就是说，评估语言会扩展，而不是只保留监督学习式推荐指标。

## 这份复用关系对当前项目的意义

这份梳理的真正意义在于确认：

- 当前项目不是另起炉灶
- 而是在一个已经跑通的序列推荐骨架上，补齐离线 RL 的决策与价值学习层

从工程工作量上看，这能把当前项目真正聚焦到新的难点上：

- 如何构建离线经验池

- 如何稳定训练 `Double DQN`
- 如何在测试轨迹上做累计奖励与 top-k 排序联合评估
